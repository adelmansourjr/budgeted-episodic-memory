# Can question-last tuning beat frozen question-last Qwen?

The previous reader adaptation improved on frozen question-first Qwen. On a separate comparison-question panel the strongest observed frozen control put the question after the evidence. This experiment uses that exact ordering for both adaptive training and held-out inference, so any paired improvement is attributable to checkpoint adaptation under that prompt and acquisition policy.

Start from the existing local 4-bit Qwen3-1.7B base checkpoint. Use the same rank-8, scale-2 low-rank modules on the final four Qwen blocks as the earlier answer-only adapter. Keep the same 640 annotated training representatives and 64 checkpoint-selection representatives, using the frozen reveal-bridge acquired articles and the earlier token-preserving question-last permutation. Sentence support targets are not part of adaptation. Train one pass with 160 AdamW updates at 0.0002, weight decay 0.01, four single-case microsteps per update and gradient clipping at one. Answer likelihood includes a stop target subject to the 24-token output budget. Checkpoint candidates are updates 40, 80 and 160. At each candidate evaluate LoRA gain 0.5 and 1.0, implemented by scaling the B tensors before inference. Select the single highest mean generated answer F1 across the 64 development representatives. Break ties by earlier update then smaller gain. Freeze that choice before scoring any held-out question.

Compare three readers on exactly the same prompts and token IDs: the new question-last adapter, the original frozen model, and the previously selected answer-only question-first adapter applied to the new question-last format. Frozen question-last is the primary comparator: it was the strongest frozen prompt in the earlier fixed-budget comparison and shares the desired base checkpoint and input content. The earlier adapter is a secondary check of whether matching training and inference order is beneficial. No alternative model, additional retrieval or auxiliary generation is available to any arm.

Use 320 unused HotpotQA components selected from index 5304 onward after excluding exact normalized test support-title overlap with fitting gold titles or acquired training/development text. A case is one deterministic representative of its connected support-title component. Require at least +3 answer-F1 points for the new adapter over frozen question-last and a positive lower end of the paired percentile 95% interval over 20,000 component draws. Report exact match, generated token counts, wins/ties/losses, confidence intervals, and secondary contrasts. Quantities are conditional on the single training seed and the sampled components.

All arms use greedy generation, the first nonempty line scorer, at most 1,024 prompt tokens, and the same 24-token generation cap. Count realized generation separately. Prefix activation reuse may accelerate evaluation only after exact generated-text and token-count checks against standard full-prompt inference on development questions. Retain the full logical token count when using cached states. Use one local model and one active sequence. Publish numeric ledgers, fingerprints, code and the selected adapter separately from the raw data.
