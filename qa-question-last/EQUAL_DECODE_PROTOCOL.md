# Exact answer-token comparison on MuSiQue

The published question-last adapter gained 6.69 F1 points under a common 24-token cap while generating more tokens on average. This follow-up compares the same saved adapter and frozen Qwen3-1.7B at the exact same generated and scored tokenizer lengths on every case.

Use the existing 169-group transfer panel as the primary panel. Use the disjoint earlier 160-group MuSiQue panel as a replication, converted to the same token-preserving question-last format. That panel was previously evaluated with question-first readers; it has no earlier results for this checkpoint under the present decoding policy. Keep the prior fixed acquisition, title screen, one representative per support component, and logical input token IDs identical across readers. Freeze adapter, base checkpoint, prompts, outcome definitions and lengths before the run.

Use greedy decoding and block all special and out-of-vocabulary IDs, all tokens whose single-token decode contains a line break, and all tokens with no visible non-whitespace character. This suppresses early EOS and whitespace-only continuation. Emit twelve ordinary tokens for every reader and case. The primary compares the whole decoded first **six tokenizer tokens** using MuSiQue alias-aware token F1. Six is a fixed short-answer length near the previously reported adapted mean of 5.73 tokens. Score every question in both panels. Score the entire prefix and preserve ordinary punctuation and whitespace normalization from the official metric. Keep no first-line or answer-header extraction. The two arms use exactly the same number of generated tokens and the same number of prefix tokens in each comparison.

Verify that standard forced greedy decoding and shared-prefix decoding emit exactly the same token IDs on earlier development prompts, and verify that a standalone six-token run matches the six-token prefix of a twelve-token trajectory. The development check uses no MuSiQue outcomes. Fall back to standard decoding if shared-prefix results differ. Use one local model, one active trajectory and one set of model weights. The adapter and frozen Qwen use the same decode mask. MLX's internal one-token lookahead applies equally to both arms.

The two-reader paired F1 effect on the 169-group panel at six tokens is primary. Require at least +3 F1 points in the estimate and a positive lower bound of the 95% paired percentile interval to call a practical gain. Test the independent 160-group panel at six tokens by the same rule. Call the effect replicated only if both panels qualify. Report exact match, wins/ties/losses and a secondary pair-bootstrap pooled estimate with groups resampled within their two panels. Report the fixed 2-, 4-, 8- and 12-token sensitivities and a joint 95% bootstrap band for the pooled length curve. Their point estimates are descriptive unless the simultaneous interval supports a claim.

As a separate descriptive check, record the first step where unmasked greedy decoding would select a blocked token on the constrained trajectory. Before that step, the two paths agree exactly. For each case, score both readers on the shorter such prefix and include every case, including empty prefixes. This matches scored prefixes before either policy intervention. It also chooses length by model behavior and serves as a sensitivity check. Actual generated length remains twelve tokens for the primary. The exact-length policy may require a reader to continue beyond its preferred answer endpoint. Interpret the result as a controlled decoding comparison.
