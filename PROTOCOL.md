# Held-out protocol for budgeted multi-hop memory

The question is whether newly revealed evidence helps an inexpensive search policy recover a complete support set under a fixed reading budget. The intervention changes what the search policy can use after each read. Both variants start from identical compressed memories. Reading the first 24 words and article title of each passage is the synthetic index construction rule. This is a text evidence proxy for episodic memory and adaptive visual retrieval.

## Data and observable information

Use the 2,417 rows of the official public MuSiQue-Ans development file as a closed corpus of candidate episodes. Each question has 20 provided candidate paragraphs. The original MuSiQue test set is outside this study. Build connected components across identical normalized gold article titles, supporting paragraph text and source single-hop question IDs to prevent direct overlap across internal splits. This metadata is used for splitting and scoring only. The largest component is a separate single-topic stress set. Hash remaining groups into development and held-out evaluation using the documented salt and one-of-five group buckets. The development set chooses policy weights and comparator. Do not inspect held-out outcomes before writing FROZEN.json.

Each policy gets the question, readable title, first 24 word tokens and purchasable tail length for each candidate. It receives no answer, question decomposition, support label, original paragraph index or dataset order. Candidate order derives deterministically from a salted hash of the episode ID and candidate slot and is treated as an arbitrary tie-breaker. A purchase costs the tail word count plus one overhead unit, even when the preview already contains all words. Title and preview word counts are charged as fixed shared index size and shown separately. This budget models word observations, not model-token counts or compute. Reading all candidate metadata is part of the measured setup. All policies use the same ledger and cannot read a repeat or exceed the cap. Candidate length is public for budget feasibility. We do not assume candidate sets replicate open-corpus search.

## Methods and endpoints

Seven policies share the same compressed index and budgets. BM25 and TF-IDF cosine are static lexical references. Relevance/redundancy MMR and residual-query coverage are strong preview-only allocation controls. Iterative BM25 expands from previously purchased passages with locally inverse-frequency weighted term feedback. The proposed bridge policy emphasizes specific links between new evidence and candidate previews or titles. Its closest control runs the same algorithm with only visible previews, even after purchases. Both use independent six-setting grids of identical size. Word access is instrumented. Only purchased tails can change full-evidence rankings.

Primary endpoint is the proportion of ordinary held-out questions for which all annotated supporting paragraphs were purchased, at 320 word units and 24 preview words. Compare reveal-based bridging against the strongest control selected on development. This benchmark tests support acquisition. It does not evaluate question-answer accuracy, the sufficiency of annotations, thoughts or video processing. Also report support recall, realized spend, reads, index word count, and index setup plus policy CPU. The labelled oracle gives the maximum attainable support count at the same budget by purchasing the cheapest gold tails. Its estimates are a bound with label access, not a deployable baseline.

Require improvement of at least 2 percentage points and a two-sided paired 95% component-bootstrap lower limit above zero for the primary practical-gain declaration. Resample complete components with replacement and recompute the question-weighted difference; also report component-weighted sensitivity. The interval describes corpus-component variation, not a guarantee for other corpora. Predeclare direct comparison against iterative expansion as secondary. Report finite sensitivity to 8 and 48 preview words (no retuning), 192 and 512 word caps, equal four reads, each hop count, and the single largest topic. The latter has no across-topic confidence interval. Retain every comparison and failure; follow-up changes require a new version and independent data.

## Finite routing result

We separately prove a best fixed-batch evidence-coverage recursion for a routing tree with arbitrary positive integer per-node prices and finite leaf probabilities. When the route is revealed node by node, the optimal adaptive coverage is the probability of leaves with individually affordable root-to-leaf paths. The proof concerns known finite branching and exact observed pointers, not neural or natural-language performance. Exhaustive subset tests verify the frontiers on a heterogeneous-cost witness. The synthetic proof and real-text replay support complementary conclusions.

## Replay and limits

No external embedding, language model, video, or GPU download. Python, one CPU process, NumPy. Publish the pinned data hash, exact policy rank configurations, selection logs with original dataset IDs, intervals, program checks and a replay command. No raw article text or answers are republished. The development partition is constructed from a public benchmark, so the results do not represent a blind community leaderboard. Shared distractors and paraphrases can remain across groups even though supported title and question source IDs are disjoint.
