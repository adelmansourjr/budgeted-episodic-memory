# Prospective comparison-question follow-up

Support supervision was inconclusive overall on the 320-question HotpotQA evaluation. A descriptive split in that evaluation (found after inspecting the completed outcomes) suggested a gain on the 61 comparison questions. This separate check tests that scoped effect on previously unused comparison questions, with both saved adapters fixed and still conditioned on identical inputs.

From the unused support-component order after index 4291, take the first 192 eligible representative HotpotQA comparison questions. Exclude components that share a normalized gold supporting title with the earlier acquired training or development text. Do not choose questions using their answers or previous scores. The support and answer-only adapters retain the exact same question-first prompt. For a harder frozen baseline, permute the question block to the end of the passages. Its input token multiset and length remain exactly the same. Include the original frozen question-first prompt as a fourth control to isolate the effect of token order without adaptation. All readers get a greedy 24-token output cap. Score all cases once.

The practical threshold remains +3 answer-F1 points and a positive lower end of the 95% paired bootstrap interval for support versus answer-only. The question-last frozen contrast is an additional test against a stronger prompting baseline, not a direct estimate of the effect of training under identical ordering. Report it with its own paired interval and retain the earlier mixed-panel primary result. Because the new question type was motivated by an earlier exploratory split, assess replication only on the new comparison questions.

The question-first arms can reuse the prompt prefix activations and K/V entries of layers below their adapter boundary. Check equivalence against standard full-prompt generation on the first six development cases for every question-first reader before final scoring. If any generated string or token count differs, use standard generation throughout. Token accounting remains logical full-stream accounting even when computation is shared. The cache does not consume extra evidence or extra generated tokens.
